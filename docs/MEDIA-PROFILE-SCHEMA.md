# Media profile schema (FS-06, binding contract)

Sibling of [DEVICE-PROFILE-SCHEMA.md](DEVICE-PROFILE-SCHEMA.md). One JSON file per test medium:
`app/media/profiles/<id>.json` (UTF-8, 2-space indent). `app/media/index.json` is generated by
`node tools/build-media-index.mjs` (`--check` in CI). Validation: `validateMediaProfile` in
`app/media-library.js` (JS) and `validate_profile` in `src-tauri/src/media.rs` (Rust); keep them in step.

Rules that matter more than the format:
- **Facts only, with provenance.** Every built-in carries `sources[]`. Unknown values are `null` and the
  entry is `"confidence": "unverified"`. Never invent track data, levels or sides; leave the field out
  (or `null`) and say what is unknown in `notes`. Audio from commercial records is never shipped.
- `confirmed` is only for values read from a primary source (currently: xwax `timecoder.c` for the
  timecode formats). A built-in marked `confirmed` must have at least one `sources[].verified: true`
  and every `confirmed` track needs a `source` URL.
- **Timecode facts have one home: `TIMECODE_FORMATS` in `app/timecode.js`.** Built-in timecode media only
  name the format (`timecode.formatName`); carrier, rpm, phase convention and side lengths resolve through
  `toTimecodeFormat()` and a CI test checks every built-in against the table. Built-ins must not repeat
  `carrierHz`/`sides`.

```jsonc
{
  "schemaVersion": 1,
  "id": "ortofon-test-record",            // built-in: kebab-case, <= 64 chars. custom: generated UUID, never user-supplied
  "version": 1,                           // integer >= 1; bump on any content change so installs update
  "kind": "test_record|timecode|tone_file",
  "manufacturer": "Ortofon" | null,
  "name": "Ortofon Stereo Test Record",
  "playbackRpm": 33.333 | null,
  "confidence": "confirmed|unverified",   // medium-level; the weakest of medium/track/format wins in expectedValuesFor
  "rias": "text" ,                        // optional free text
  "notes": "what is unknown / how to verify",
  "productProfileId": "serato-control-vinyl-cv025",  // optional: device profile (category timecode-media) this medium is the primary medium of
  "tracks": [{
    "key": "t5",                          // 1-32 of [A-Za-z0-9_-], unique per medium; stored on results as media_track_key
    "side": "A" | null, "trackNo": 5 | null,
    "purpose": "reference_tone|speed_tone|sweep|tracking|anti_skate|wow_flutter|vta|balance|square_wave|noise|silence|other",
    "frequencyHz": 1000 | null,           // > 0; null for sweeps/noise/unknown
    "level": { "value": 5, "unit": "cm/s_rms|um_peak|db|dbfs" } | null,
    "durationS": 28 | null,
    "channel": "L|R|both" | null,
    "label": "short text", "notes": "text",
    "confidence": "confirmed|unverified",
    "source": "https://..."               // https only
  }],
  "timecode": null | {                    // required (object) iff kind == "timecode"
    "formatName": "Serato CV02.5",        // must match a TIMECODE_FORMATS name for built-ins
    "hasNoiseMap": true,                  // optional attribute; does not change the carrier
    "carrierHz": 1500, "atRpm": 33.333    // CUSTOM media only (a user-defined format); forbidden in built-ins
  },
  "sources": [{ "title": "...", "url": "https://...", "verified": false }]
}
```

Limits (also enforced in Rust): import JSON <= 256 KB, <= 100 tracks, text fields <= 500 characters,
every URL `https` (shown, opened only through the allowlisted opener, FS-07). A built-in id can never be
overwritten by an import (`id-collision`). Custom ids are always generated; an import that names an existing
custom id edits it, anything else gets a fresh UUID.

## Expected values and prefill

`expectedValuesFor(media, trackKey, testId)` returns `null` when the medium does not fit the test
(`TEST_KINDS`: speed = record/tone/timecode, cartridge = record/tone, dvs and timecode = timecode) or
`{referenceHz?, levelCmPerS?, carrierHz?, nominalRpm?, formatName?, trackNo?, confidence, unverified, warning, label}`.
Unknown values are absent. `unverified: true` carries the warning "Unverified — confirm on your disc".
Precedence for the reference frequency (`prefillReferenceHz`): user override > medium track > device
profile > 1000 Hz. `suggestNominal` implements "Looks like a 3150 Hz record — switch?" (1 % window over
`[1000, 3000, 3150]`).

## Database

Migration `0004_test_media.sql`: `test_media` (profile row, `owned`, `retired`), `test_media_track`
(one row per track, replaced on update) and nullable `device_test_result.media_id` / `media_track_key`.
`media_profiles_sync` (see `src-tauri/src/media.rs`):
- inserts/updates built-ins when the stored JSON or the resolved device link differs; **retires**
  (flag, never deletes) built-ins that stop shipping; an empty list retires nothing; custom rows,
  `owned` flags and saved results are never touched;
- the JS side adds `timecodeFacts` (`{formatName, vendor, carrierHz, atRpm, sides[{label, durationSec}]}`,
  resolved from `TIMECODE_FORMATS`; `durationSec = lengthCycles / resolution`). It is not stored. For a media
  with `productProfileId` whose device profile is already synced, it upserts `dvs_media_profile` and one
  `dvs_media_side` row per side (`id = <mediaId>:side:<label>`, `duration_sec`, `nominal_rpm`). Only the primary
  medium of a device profile is linked (one `dvs_media_profile` row per product): currently
  `serato-cv025` and `traktor-scratch-mk2`. Sync device profiles first, then media.
- `media_custom_delete` retires (hides) a custom medium that saved results still reference, otherwise deletes it.

Browser mode (no Tauri): `createMediaStore({storage})` keeps the same state under `deckchek.media.v1`.

## Adding a medium you own (template)

Technics/Pioneer test records are intentionally not shipped (track data unknown). To add one, use
"Add custom medium" or import a file like:

```json
{ "schemaVersion": 1, "version": 1, "kind": "test_record", "name": "My test record",
  "manufacturer": "Maker", "playbackRpm": 33.333, "confidence": "unverified",
  "tracks": [{ "key": "t1", "trackNo": 1, "purpose": "speed_tone", "frequencyHz": 3150 }],
  "timecode": null }
```
