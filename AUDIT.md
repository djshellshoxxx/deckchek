# DeckChek audit (AI-assisted review)

This is an AI-assisted review. Claude Code agents did the work, and other agents tried to refute each finding. It is not an independent professional audit, and it is no guarantee of security. A clean row here means the reviewers found a fix and a named test. It does not mean the area is free of bugs.

**Scope.** All Rust modules in `src-tauri/src`, the JavaScript in `app/`, the Tauri capability files, `src-tauri/tauri.conf.json` and the CI workflows in `.github/workflows`. The review was run against commit 41e24f8. Statuses were checked against the working tree at 8451f76, which is one release-prep commit later. That commit changes the app version (`Cargo.toml`, `Cargo.lock`, `tauri.conf.json`), adds `THIRD-PARTY-NOTICES.md` with its generator `tools/third-party-notices.mjs` and a release-workflow check step, and adds the ui-smoke temp-folder cleanup (INT-05). No other row is affected.

**Threat model.** DeckChek is a single-user, offline desktop app. We treat these as hostile:

- files the user opens (backups, workspaces, packs, certificates, mappings, learned maps, ledgers);
- device names, MIDI and audio port names, and logs that come from the system;
- a compromised WebView. This is defence in depth: Rust commands should not trust what the page sends.

Attackers who can already write the user's files or run code as the user are out of scope.

**Method.**

- One audit of the existing modules (AUD rows).
- Four feature reviews (R1 to R4). Each finding went to verifiers who start from "refute by default". A finding is listed as confirmed only if it survived that check. Disputed findings are kept and marked.
- Fuzzing: cargo-fuzz on the Rust parsers and a seeded JS fuzzer on the JS parsers (FUZZ rows).
- Integration findings from merging the features together (INT rows).

Each status was checked by reading the code, not by trusting commit messages. The test suites were not re-run while this report was written. A test named in the Verification column was found by name in the repository.

Some reviewer lenses reported the same defect twice. Those rows are kept and marked as duplicates, so the counts below include them.

- R1-34 and R3-23: double submits are blocked in the UI only. The server mints a new id per call and has no idempotency key. The service UI still cannot delete a part or labour entry.
- R1-15 and R1-32: the venue-rename test runs against the in-memory mock. There is no Rust test.
- R1-03: compareToSpec still matches units by first word. The Spec tab uses compareMetricToSpec, which checks the exact unit.
- R2-09: no test fires the tray toggle or quit events while the liveMonitor flag is off.
- R2-13: the open() error branches have no dedicated test.
- R2-15: log_append has no distinct "session ended" error, so the JS side counts those rows as dropped.
- R2-20: the Delete button still shows on the running session row. Rust refuses the delete and the UI shows an error toast.
- R3-03: the doc comment on modelUncertainty (app/certificate.js:140-145) still describes the old stored shape.
- R3-24: backups still contain the customer table, by design. The UI now says so.
- R4-01: when ledger_write_folder is not available, the fallback through userfiles_write_folder does not prune stale files. It shows a note asking the user to remove them instead.
- R4-19: files are moved in one at a time. There is no whole-directory swap, so a failure part-way can leave a few same-named photos replaced under the old index.
- docs/qa.md still says the Rust fuzz smoke has 9 targets and the JS fuzz smoke has 10. The code has 11 and 13. docs/IMPLEMENTATION-STATUS.md has the right counts.

## How to re-check

Run these from the repository root unless noted.

```sh
npm test                          # JS unit and regression tests (node --test)
cd src-tauri && cargo test        # Rust unit and regression tests, including the fuzz replay smoke
node tools/ui-smoke.mjs           # Playwright UI smoke checks (fleet, compare, monitor, ledger, ...)
node tools/fuzz-js.mjs            # seeded JS fuzzing of the JS parsers
```

For longer Rust fuzzing, run from `src-tauri`:

```sh
cd src-tauri
cargo +nightly fuzz list
cargo +nightly fuzz run <target>
```

Crashes that were found and fixed are kept under `src-tauri/fuzz/regressions/<target>/` and replayed by `cargo test`.
